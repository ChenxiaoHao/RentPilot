# AI 找房闭环交付记录

2026-10-31。完成路线图第一步：扩大通勤候选覆盖、无匹配时预览调整、确认后重新查找。[实现计划](../superpowers/plans/2026-10-31-search-closure.md)。保持 Vue 3 + TypeScript + Capacitor、Spring AI、高德及现有黑白灰界面、四项胶囊导航；不开发方案或 LifeSim。

## 完成的行为

- 按不同小区参考坐标分组，每批默认核验最近 12 个坐标及其全部匹配房源；同坐标房源共享路线请求。
- 有未核验坐标时提供“继续核验”，保留条件并累计核验数量及合格结果，不再次调用模型。每次最多展示六套。
- 部分路线失败的坐标保留待重试，已成功坐标不重复查询；整批失败显示错误，不计作没有房源。只有缺失坐标时不提供无效的继续入口。
- 无匹配时提供预算或通勤上限调整建议，数值来自现有目录或已观察路线。一次只调整一个字段，区域、出租方式、居室、工作地和其他条件保留。
- 点击建议只打开预览；“保持原条件”不请求接口；“确认并重新查找”才提交结构化操作。单独一句“可以”不自动选取调整方案。
- 普通自然语言修改启动新搜索；确认过的调整保留在模型对话中，旧续查操作不会混入新条件。
- 新对话、账号切换、取消和重试隔离；待重试操作与工作地上下文可恢复。长时间续查保存时压缩旧续查记录，保留原始条件、明确修改和最近进度，避免原始需求被截掉。
- 确认弹层只显示变更、其他条件不变及必要的筛选说明；页面已有具体核验数量时隐藏重复的通用说明。使用 design-taste-frontend 的 App 规则检查。

## 排查与修复

初次真实续查出现高德限频，未作为无匹配处理。进一步在同等并发下诊断，24 次快速路线请求中 20 次返回 `10021 CUQPS_HAS_EXCEEDED_THE_LIMIT`，见 [脱敏诊断](provider-diagnostic.json)。因此给网关未缓存路线请求增加 500ms 的启动间隔，缓存命中无需等待；等待被取消后不会继续请求。修复后上述真实完整流程全部通过，没有通过提高并发或自动重试掩盖问题。

其他回归包括：部分失败的最后一批可继续核验、过期令牌重新检索、非法调整选项、预算调整保留硬条件、长续查后恢复原始需求、账号切换关闭旧确认弹层。独立审查提出的“通勤上限在住房 criteria 中陈旧”经接口核对撤回：住房 criteria 不包含通勤字段，实际值位于 commute.maxMinutes，确认文字也保留在后续模型历史中。

## 能力边界

搜索进度为最多 128 个进程内快照，每个有效期 10 分钟；重启或淘汰后会明确提示重新检索。当前不提供跨设备进度同步。房源仍全部为模拟数据，坐标是小区参考位置，照片为室内示意；路线是预计值，不保证门到门或高峰时间。未核验候选不能宣称符合或不符合，只有已核验合格房源进入通勤推荐。仅筛选条件的预算预览不保证符合通勤，必须确认后再核验。方案优化、LifeSim 和真实房东认证不属于本轮交付。
