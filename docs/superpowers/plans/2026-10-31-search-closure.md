# AI 找房闭环：覆盖扩展与确认调整

用户批准执行路线图第一步。延续既有找房流程，保持黑白灰、胶囊导航、Vue/TS/Capacitor/Spring AI，无原 CSV 或现有账户数据改写。代码任务只使用 gpt-6.1-terra。本轮不开发方案、解释排名、LifeSim 或云端部署。

## 用户行为与验收

1. 候选按坐标分组后核验，每批默认最多 12 个不同坐标；同一坐标的全部基础匹配房源共享路线结果，避免把 12 套误当成 12 个地点。
2. 尚有可核验候选时，可点击“继续核验”；保持原工作地、预算、交通方式、居室和其他硬条件，累积核验结果、去重房源，最多展示六套。不重复调用模型提取同一批条件。
3. 无匹配时最多两个数据支持的调整选项：预算上限、通勤上限。预览写清哪一项从多少改到多少，其他条件保持；数据库筛选候选不能冒充路线合格数量。
4. 点击建议仅打开确认预览；“保持原条件”不发请求。“确认并重新查找”才提交结构化操作，服务端只修改所选字段，避免模型误解或静默放宽。
5. 普通自然语言修改仍走模型提取并覆盖最后明确要求；简短肯定不自动应用多个建议。地点/预算/方式改变不得续用旧搜索进度。
6. 新对话、切换账号、取消、失败重试、刷新恢复保持隔离；操作过期提供明确错误，重试可按对话重新开始，避免永久重复过期令牌。

## 兼容接口（确定后前后端并行）

现有 `POST /api/ai/search` 消息和地点参数保留，新增可选：

```ts
type SearchAction = {
  type: 'CONTINUE' | 'APPLY_ADJUSTMENT'
  token: string
  adjustmentId?: string // 仅 APPLY_ADJUSTMENT
}
```

Request 新增 `action?: SearchAction`。这是用户明确点击或确认的操作；服务端从不可猜测令牌关联的短期快照恢复条件，不依赖客户端提供坐标、任意字段补丁或助手文本。继续查询与确认调整不重复调用模型。

Response 可选/可空新增：

```ts
searchToken?: string
hasMore?: boolean
adjustments?: {
  id: string
  label: string
  description: string
  changes: { field: 'maxRent' | 'maxCommuteMinutes'; from: number; to: number }[]
  previewCount: number
  previewKind: 'FILTER_ONLY' | 'VERIFIED_ROUTE'
}[]
```

旧响应无以上字段仍能使用。`hasMore` 表示还有实际可请求路线的坐标组，只有缺失坐标时为 false。`commute` 核验数量累计，缺失坐标/失败保持未核验；`total` 为已核验合格数。全部供应商请求失败返回错误，不能变成目录无结果。

快照为进程内有界存储（至多 128 个，TTL 10 分钟），不引入数据库/新技术栈；随机令牌无密钥/对话明文，过期或不存在返回 409 `AI_SEARCH_EXPIRED`。重复操作幂等，路线并发和阶段时限仍有界。后端重启清除快照，前端按错误提示重新检索。快照只存当前查询与进度，不读写用户账户资源。
