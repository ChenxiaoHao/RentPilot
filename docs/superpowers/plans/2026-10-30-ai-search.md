# RentPilot Spring AI 寻房实现计划

> For agentic workers: use executing-plans or subagent-driven-development; only GPT-6.1 Terra for delegated development, per user preference.

**Goal:** 用户从现有聊天页描述/修改需求，Spring AI 提取条件，后端只读检索1500条模拟房源，返回可追溯推荐、追问或无匹配结果。
**Architecture:** Stateless bounded conversation -> model extraction -> strict criteria validation -> existing ListingRepository -> deterministic factual explanation/cards. Model credentials are server-only and explicitly configured, never inherited from other applications' global API keys. No simulated model fallback in the product.
**Stack:** existing Vue3/TS/Pinia/Capacitor, Spring Boot3.5/Java21, compatible Spring AI1.1.x. No DB migration or CSV changes.
**Spec / authorized scope:** user's 2026-10-30 approval of the AI search vertical slice. Existing monochrome/mobile chat layout and capsule navigation retained; other demo plan/LifeSim pages retain labels.

## API contract

POST `/api/ai/search`, JSON `{messages:[{role:'user'|'assistant',content:string}]}`. Bound history and body sizes; last message must be user. Only human requirements drive extraction. Ignore assistant content for authoritative constraints. No arbitrary model-returned SQL/URLs/tool execution.

Success JSON: `{status:'NEEDS_INPUT'|'MATCHES'|'NO_MATCH',message:string,criteria:object,recommendations:[{listing:existingListingRecord,reasons:string[]}],total:number,limitations:string[],dataKind:'SIMULATED',source:existingDatasetInfo,engine:'SPRING_AI'}`. Criteria contains only validated, existing list API filter keys, omitting unset values. At most6 recommendations. All item facts and reasons originate from database fields. Model raw reply never rendered as factual recommendation.

Missing explicit provider configuration ->503 `AI_NOT_CONFIGURED`; unavailable provider ->503/502 with sanitized message; malformed extraction ->502 `AI_INVALID_RESPONSE`. No key or raw provider bodies in logs/errors. Unsupported hard workplace commute/POI requirements must lead to transparent clarification, never claim verified commute. Need budget/location clarification when underspecified, preserve human changes/negations across turns, never silently relax constraints on empty results.

## Review focus

1. Later budget/area changes and removed conditions must not retain stale recommendations.
2. Account/new-conversation switches and delayed replies must not overwrite a different conversation.
3. Unknown facilities/coordinates and metro walking time must not turn into claims about real rental availability or workplace commute.
4. Provider credentials/HTTP errors must not leak, and absent provider must not prevent catalog startup.
5. Empty result, malformed output, model timeout and external cancellation remain distinct and retryable.
