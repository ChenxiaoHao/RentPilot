# 房源列表接线

本轮按用户要求只接前端房源列表和可复用照片；保留既有黑白灰和胶囊导航，不继续扩展 AI、地图或规划业务。

- 新增 `/listings` 作为底部“找房”入口，真实请求 `/api/listings` 和 `/api/listing-filters`；原 `/map` 及原样例详情不变，仍为独立点位示意。
- 搜索、行政区、预算、出租方式、卧室数、地铁步行和排序交给数据库；默认不隐藏条件、不限制为一居。20 条一页，可继续加载；筛选变化回到第一页，旧请求不能覆盖新结果。
- 点击房源在弹层查看原数据；不把后端编号送到只认识 h1–h6 的旧详情页。保留 null、UNKNOWN、押金和物业费周期不明等含义，不添加评分或工作地通勤。
- 选用 Pexels 明确免费许可的卧室/公寓图片，保存本地与来源清单。稳定按房型和编号复用，仅作为室内示意，不代表该小区实拍。图片坏链有本地占位。
- Web 开发/预览通过 Vite `/api` 代理；Android 通过 Capacitor 原生 HTTP 请求本机接口，Debug 仅允许 10.0.2.2/127.0.0.1 的明文连接。Release 不放宽安全策略，部署时配置 HTTPS 地址。
- 加载、空结果、断网/后端不可用、加载更多失败均有独立状态，不退回旧示例冒充查询成功。
- 先写失败浏览器测试，再实现，跑全套单元/端到端、构建、Capacitor 同步；若模拟器可用则实际验证原生请求。
- taste-skill 延续既有 achromatic-ledger 方向，不重新抽取整套视觉。问题：预算和房型条件下有哪些可选模拟房源？价格最大，区域/户型/地铁信息次级，图片不是数据证据。
