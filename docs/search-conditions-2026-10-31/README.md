# 找房条件面板改造

2026-10-31。按用户要求暂停方案保存阶段，先修复预算、工作地点、通勤方式和横向溢出。[实现计划](../superpowers/plans/2026-10-31-search-conditions-panel.md)。本轮仅修改前端与相关测试、文档，后端接口、原 CSV 和现有账户数据不变。

## 问题原因与结果

旧 ChatPage 将滑块范围写成 2500–8000，默认工作地写为张江高科，草稿固定整租一居，而且没有交通方式字段。这些是前端预设，不是数据最低价或实际用户条件。

原模拟数据最低月租为 900 元，低于 1000 元有 73 条，均为合租；没有为演示新增或调低任何房源价格。

- **预算**：改为最低/最高租金手填，支持 0、500、800、900 等值，空值表示对应边界不限。提供三个常用区间与清空租金，取消原生滑块；负数、非金额、超过两位小数、反向区间或超过后端九位整数范围会在提交时提示，不偷偷修改输入。
- **工作地点**：新对话不预填具体地点；支持上海的区、街道/镇联动及企业/园区/道路门牌自由填写。改变区清除不属于该区的旧街镇。目录失败可重试，也可继续手填地址。
- **租赁方式**：不限/整租/合租，初始不限。仅在整租时提供居室选择，切换合租会清除旧的整套居室限制；不再固定整租一居。
- **通勤**：步行、骑行、公共交通、驾车直接在面板选择，不暗选，提交前校验；公共交通表示公交或地铁。时间提供 15/30/45/60 分钟，已有查询的 36 分钟等值也会明确显示。
- **交互**：“填入对话”只生成可编辑草稿，不自动发送或调用模型。工作地区不会被当作住房地区；预算不限、租赁不限等选择会明确覆盖之前相关约束。
- **回填与隔离**：回填已确认工作地点、预算、租赁方式、交通和时长，同一上下文关闭重开保留编辑。新对话、账号或历史对话切换时关闭弹层、清空旧条件、未发送文本和本地参考图，避免串用。
- **布局**：分组标题与两列输入统一，正文可纵向滚动、底部按钮固定可达。402×874 下能看到全部交通和时间选项；320 与短屏保留正常纵向滚动，没有横向滚动条。

cd android
