# 第二步：推荐依据与费用交付记录

2026-10-31。完成 [实现计划](../superpowers/plans/2026-10-31-recommendation-evidence.md) 中的推荐依据、费用明细、排序说明和按需 Spring AI 解读。沿用 Vue 3、TypeScript、Capacitor、Spring AI 1.1.8 和高德，保持四项胶囊导航与黑白灰界面，没有修改原 CSV、账户数据或数据库结构。

## 现在如何使用

打开 `http://127.0.0.1:5178/#/chat`，刷新后新建对话并发送找房需求。推荐卡片下显示最多三条简短依据；点击“推荐依据与费用”展开，再点击“AI 解读”请求模型。仅展开或收起不调用解读模型。

- 依据按当前硬条件与实际房源字段计算，通勤和预算优先出现在短理由中。未知设施与物业费周期保留“待确认”。
- 费用分开显示月租、周期未注明的物业费、一次性押金、付款方式和“首期租金 + 押金”。没有将押金算作月费，也没有把未知费用按零计入完整生活成本。
- 只解析目录已明确支持的押一付一、押一付三、押二付三，分别按 1、3、3 个月租金计算首期；押金取源字段，不按“押几”重新推算。未知付款方式的首期金额保持未知。
- 普通 AI 筛选按月租由低到高；通勤推荐按预计通勤时长优先，同等通勤月租更低。部分核验时明确说明覆盖范围，不提供无来源的匹配分数。
- 解读加载时可取消，失败时可重试；结果过期提示重新查找。切换查询、账号或新对话后，旧请求不会写入新上下文。旧历史响应没有新增字段时仍正常显示。

## AI 解读的真实边界

`POST /api/ai/explain` 只接收 `searchToken` 和 `listingId`。后端从该搜索快照恢复已实际展示的最多六套房源及证据，客户端不能提供或改写金额与事实。

模型通过现有 Spring AI 客户端，从已提供证据中选择 1–3 个不重复 ID，至少一个为已匹配事实。后端拒绝未知 ID、自由事实字段、重复键、尾随内容、空输出和截断输出，再将选中证据的可信文字组装为简短解读。模型负责选择解读重点，文字与数字来自服务端证据；没有把模型自由生成的内容当成房源事实。

成功结果按搜索票据和房源缓存，改变条件后不会复用旧票据的解读。模型失败返回 `AI_EXPLANATION_UNAVAILABLE`，事实与费用明细仍可查看；过期返回 `AI_SEARCH_EXPIRED`。凭据仍仅保存在被忽略的本机后端配置文件中，前端没有模型密钥。
