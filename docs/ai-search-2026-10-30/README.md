## 功能与边界

聊天页调用 `POST /api/ai/search`。后端用 Spring AI 提取按时间更新后的结构化条件，通过现有 ListingRepository 只读查询模拟房源，最多返回六条。房源编号、租金、区域、面积和推荐理由来自数据库，不使用模型生成的房源事实。

返回状态：`NEEDS_INPUT`（补充条件）、`MATCHES`（候选房源）、`NO_MATCH`（保持条件后无结果）。工作地实际通勤和生活配套尚无计算/核验接口，不能因临近地铁就声称满足通勤要求。方案生成、权重、LifeSim、版本比较仍为独立本地演示，本轮没有将它们接入模型。

模型只在服务端配置，前端没有密钥。未配置返回503 `AI_NOT_CONFIGURED`，服务失败和错误格式会显示可重试错误，不回退固定示例回复。参考 [Spring AI 官方文档](https://docs.spring.io/spring-ai/reference/index.html)。

## 配置真实模型

本机 `backend/config/application-local.properties` 为已忽略的私有配置文件，现有高德配置应保留。在模型控制台取得 OpenAI-compatible Chat Completions 接口后填入：

```properties
rentpilot.ai.base-url=
rentpilot.ai.completions-path=/v1/chat/completions
rentpilot.ai.model=
rentpilot.ai.api-key=
```

`base-url` 与 `completions-path` 拼接得到服务商的完整聊天地址，避免重复 `/v1`。按服务商实际文档修改路径，不能把网页聊天地址当 API 地址。未指定默认服务商或模型，不读取其它软件使用的全局 OPENAI_API_KEY 等密钥。不要把私有配置发到聊天或提交到仓库。填好后重启后端。

## 开发与使用

从 backend 目录用现有 `scripts/start.ps1 -Build` 启动（Java21）；前端目录执行 `npm run dev -- --port 5178`，打开 `http://127.0.0.1:5178/#/chat`。

先输入“浦东新区，月租4500以内，整租一居”，再输入“预算改成4000”。检查每轮推荐满足最新条件。输入没有房源的预算应返回无匹配；只输入“想找房”应追问；输入工作地通勤要求应说明无法核验并补充可筛选条件。

聊天保留多行输入、快捷草稿、复制、重新编辑、取消和重试。历史按本机账号隔离，与房东联系消息是两套独立记录；当前 AI 对话未做服务端跨设备同步。参考图片仅本地预览，不传给模型。

## 工作地输入问题修复（同日追加）

用户提供“闵行上海交大附近上班”“闵行吴泾宝龙广场上班，3000元、整租一居、15分钟通勤”的失败截图后，发现首轮验收未覆盖完整工作地表达。旧提取结构未独立保留工作地点和通勤上限，可能混同住房区域；真实模型还复现过空输出，被统一显示为条件解析失败。

本次将工作地与住房筛选分开，回复列出已理解的工作地点、预算、出租方式、居室和通勤上限。工作地通勤未核验时，先询问是否愿意按区域搜索并暂不限通勤，收到明确同意前不放宽。目录别名按唯一匹配规范化；可安全处理可选null、JSON代码围栏和数字字符串，非法字段仍拒绝。模型输出预算默认4096，可用 `rentpilot.ai.max-output-tokens` 调整；截断/空回复分别返回明确错误，保留用户需求，不自动重试或编造结果。

聊天中相同limitations仅显示一次，独特限制保留。真实模型及浏览器验证上述原话后，明确同意“先按吴泾镇找，通勤暂时不限”返回3条模拟房源：2400、2750、2750元，均为吴泾镇整租一居；未声称它们满足15分钟通勤。截图 `live-wujing-fix-402.png`。完整后端96项、聊天专项4项通过；前端构建、Capacitor同步及Android Debug重新编译通过。真实通勤路线计算尚未实现。
