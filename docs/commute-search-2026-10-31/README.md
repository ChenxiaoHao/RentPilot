> 本文保留首轮通勤寻房验证。后续已将 12 套候选限制改为每批 12 个不同坐标，并加入累计续查和明确确认的条件调整；当前行为以 [AI 找房闭环记录](../search-closure-2026-10-31/README.md) 为准。

## 已接通的流程

聊天输入需求 → Spring AI 提取住房条件、工作地点与通勤要求 → 补充交通方式 → 必要时选择高德工作地 → 数据库筛选模拟房源 → 高德路线预计耗时核验 → 返回最多六张房源卡片。

- 支持步行、骑行、公共交通和驾车，不替用户默认选择交通方式。
- 工作地点与期望居住区域分开，校园等同名地点需要选择；选择后服务端重新查询地点详情。
- 修改预算或交通方式时携带上一轮已确认地点作为上下文；明确换工作地点后重新定位，新对话不沿用旧地点。
- 同名地点还核对用户提供的区、镇信息，区域冲突时重新查询，避免路线仍指向旧地点。
- 地点选择、失败重试和对话恢复沿用现有消息记录，不清除用户历史。
- 同一小区参考坐标的房源共享一次路线查询，核验数量按房源逐条计数。
- 按路线秒数判断上限，15 分钟接受 900 秒，拒绝 901 秒；展示分钟向上取整。
- 接口失败显示重试，不以零分钟、直线距离或地铁步行时间代替路线耗时。

## 运行与边界

网页预览：`http://127.0.0.1:5178/#/chat`。Android Studio 打开 `D:\CODE\RentPilot\frontend\android`。APK 位于 `frontend/android/app/build/outputs/apk/debug/app-debug.apk`。

模型和高德 Web 服务配置仍只放在被忽略的 `backend/config/application-local.properties`，不要放进前端环境变量。Android 模拟器默认通过 `10.0.2.2:8080` 访问宿主机后端；实体平板/手机需要可达的后端地址并重新构建同步。

当前默认每轮核验最近 12 个基础候选，可用服务端 `rentpilot.commute.max-candidates` 设置为 1–16。直线距离仅用来安排候选核验顺序，不能证明通勤满足要求。响应明确给出 `checkedCount`、`candidateCount`、`unverifiedCount` 和 `coverage`；尚未核验的房源不能算作符合或不符合。无匹配仅针对已核验子集，不表示全上海或整个目录都没有房源。

房源仍全部为模拟数据，坐标为 GCJ-02 小区参考位置，图片为室内示意。路线是小区参考位置到工作地 POI 的预计时间，不保证门到门或早晚高峰耗时。只乘地铁等额外硬性要求、生活配套核验、真实房东认证、AI 方案优化及 LifeSim 均不在本轮已完成范围内。旧的方案和生活模拟保留演示标记，不包装为真实模型结果。
